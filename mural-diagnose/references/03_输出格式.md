# 初筛输出格式（01_findings.json）

原有字段继续可用。新增的 `overall.assessment_status`、`tiles_excluded` 和 `small_model_hints_used` 用于区分影像可评性、分块覆盖和提示的实际使用情况。

```json
{
  "image": "panel-east.jpg",
  "size_wh": [2400, 1600],
  "reviewer_model": "实际使用的模型或工具名称",
  "manual_version": "mural-diagnose v1",
  "overall": {
    "content": "东墙彩绘板左半部，图案含蓝色边框与植物纹样",
    "condition": "未分级",
    "assessment_status": "部分可评估",
    "condition_reason": "已检查左上和中部；蓝色边框内有一处不规则浅色区",
    "photo_issues": "右下反光遮住线条，无法检查该处的细裂纹"
  },
  "tiles_all": ["T1", "T2", "T3", "T4"],
  "tiles_checked": ["T1", "T2", "T3"],
  "tiles_excluded": {"T4": "该区大面积反光，需补拍"},
  "findings": [
    {
      "id": "F1",
      "bbox_xywh": [430, 270, 120, 90],
      "type": "疑似表层局部缺失",
      "category": "脱落类",
      "photo_grade": "A",
      "evidence": "蓝色边框里有一块不规则浅斑，蓝线到斑缘处中断",
      "layer_exposed": "不确定",
      "confidence": "中",
      "alternatives": "也可能是后来填补的浅色材料，当前照片看不清斑缘的高低",
      "how_to_verify": "先查此处的旧照片和修补记录，再用双向斜光近拍，检查斑缘是凹下一层还是有填补材料",
      "source": "视觉模型看图"
    }
  ],
  "rejected": [],
  "small_model_hints_used": false,
  "self_check": "原图证据与范围已经核对，保留一处影像盲区"
}
```

| 字段 | 记录方法 |
|---|---|
| `overall.content` | 描述对象和照片覆盖的位置。身份、材料或年代来自项目资料时，说明资料来源。 |
| `overall.assessment_status` | 推荐用 `可评估`、`部分可评估` 或 `不可评估`。可评性限于当前影像和任务。 |
| `overall.condition` / `condition_reason` | 通常用 `未分级`，证据不足用 `无法判断`，并写当前照片能支持的结论及范围。旧版 `好` / `一般` / `差` 仍可读取。项目确有分级标准时说明尺度和依据。 |
| `overall.photo_issues` | 记录具体受限范围和影响。局部反光会影响该处浅色、细裂纹或边缘判断。 |
| `tiles_all` / `tiles_checked` / `tiles_excluded` | 每个分块要么记录已查，要么登记排除理由。部分受限的已查块在 `photo_issues` 补充描述。 |
| `id`、`bbox_xywh` | 唯一编号。左上角 x、y 与宽、高，均用基准照片像素。 |
| `type`、`category`、`photo_grade` | 初步解释、现象类别、照片可判读层级。形态清楚可直接描述，成因和材料保留假设。常用分类见 [病害百科](01_病害百科.md)。 |
| `evidence`、`confidence` | 写能在图上指出的部位、形状、颜色、分布和与图纹的关系。置信度是对当前解释的把握，B 级最高为中，C 级最高为低。 |
| `alternatives`、`how_to_verify` | 写本处仍有依据的替代解释，说明应看哪个位置、查什么资料或采用什么方法，以及检查结果如何区分。 |
| `rejected` | 有依据地排除的候选，写明位置和理由。尚无法排除的候选保留不确定性。 |
| `small_model_hints_used` | 基于提示实际回看时标为真。单独生成提示文件的事实可由流程日志查询。 |

`findings: []` 合法。按实际情况将「在已评范围内未见明显异常」或「影像不足以判断」写进 `condition_reason`，后者还需说明受限的范围。`check_findings.py` 将候选整理为原有的 `01_candidates.json` 结构，连同 `overall` 交给本 skill 的第二阶段（逐条复核）。报告里显示的「照片依据」来自复核阶段对具体判断的置信度，初筛的 `photo_grade` 保留在原有结构中。
