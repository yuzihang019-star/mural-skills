# ⑤ 生成观察卡（mural-card）

```
① 初筛 → ② AI 复核 → ③ 建议 → ④ 人工复核 →【⑤ 观察卡】
```

把人工复核后的最终结果排成一页 A4 PDF。这一步只排版，不再生成或改写任何内容。卡片上的每一句话都来自 `04_final.json`，所以和视频里展示的过程能一一对上（评分项“视频与观察卡结果一致”）。

## 前置检查

- 必须有 `04_final.json`。没有就说明人工复核还没完成，回到 ④，**不要跳过人工复核直接出卡**。
- `case_meta.json` 的 `image_source` 要填写（比赛要求注明图片来源）。没填的话，卡片上会用红字提示，提交前必须补上。

## 运行

```bash
python <skill>/scripts/render_card.py <案例文件夹> --date 2026-11-25 \
  [--extra-tool "录屏软件名：录制演示视频"] [--extra-source "赛事方提供的场景说明"]
```

产物：`05_observation_card.pdf`（A4 单页）和 `05_observation_card.png`（预览）。

文字太多时脚本会自动缩小字号，最小到 0.62 倍；再放不下会警告。这时不要硬塞，回到 ④ 的 `04_final.json` 精简文字（需要用户同意改动，改动要记进 `04_change_log.md` 的备注）。

## 生成后检查

1. 读一次 PNG 预览（只读一次，确认排版）：框和 A/B/C 标签对得上、没有文字重叠、页面底部没有被截断。
2. 用 `pdfinfo` 或同类工具确认只有 1 页（比赛规定超过 1 页只评第 1 页）。
3. 告诉用户提交前还要人工确认的事项：图片来源和授权写对了没有；所用的 AI 工具都已披露（包括录视频、剪辑时用到的 AI 功能，可以用 `--extra-tool` 补充）。

## 卡片结构（对应比赛评分点）

| 卡片区块 | 对应要求 |
|---|---|
| 原图缩略图 + 彩色框 A/B/C + 局部放大 | 原图缩略图、疑似问题标记，图像观察与原图对应 |
| 每处的现象、影响、置信度、需现场确认的点 | AI 观察说明，问题描述清晰 |
| 建议（类型、做法、依据、风险） | 1–2 条保护 / 数字展示 / 公众传播建议，说明依据和可能风险 |
| 不确定性与人工复核（含复核统计和签字） | 不确定性及人工复核提示 |
| AI 参与说明与来源披露 | 哪些由 AI 生成、哪些经人工复核；图片和工具来源 |
| 过程记录（带时间的 ①→⑤） | 关键步骤可由视频与观察卡相互核验 |
