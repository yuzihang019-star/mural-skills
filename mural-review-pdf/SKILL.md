# ③ 人工复核 PDF 工作流

读取同一案例的 `02_review.json`、`03_conservation.json` 和 `case_meta.json`。本 skill 不改动 AI 草稿的判断，只负责把每一条交到复核人手里、把复核人的决定如实记下来。

本 skill 只生成**人工复核单**这一份 PDF。病害识别与保护建议报告是另一份独立的 PDF（`03_report.pdf`），由 `mural-conserve` 的 `make_report.py` 生成。开始前确认案例文件夹里已有 `03_report.pdf`；没有的话先运行 `python <mural-conserve>/scripts/make_report.py <案例文件夹>` 补出，再生成复核单。交付时两份 PDF 分别交给用户，不要合并。

## 1. 生成复核 PDF

```bash
python <skill>/scripts/make_form.py <案例文件夹> [--title "壁画病害人工复核单"]
```

使用 Python 的 Pillow 和 ReportLab。若系统没有可嵌入的中文字体，可通过 `MURAL_CJK_FONT` 指定可用的中文 TrueType 字体文件。输出 `04_review_form.pdf`，A4。

| 页 | 内容 |
|---|---|
| 封面 | 基准图像与来源、流程所用模型、填写说明 |
| 条目目录 | 分页列出条目和对应页码。点击条目跳转至首页 |
| 每条一页起 | 条目依次为：整体观察与评估范围、每个病害区域、对象背景、整体保护思路、每条保护建议、不确定性、待核查事项。病害区域页带局部放大图和全图位置图，正文依次为「可见现象」「病害判断」「人工核查方法」「保护措施」。照片依据用「较清楚／有限／较弱」表示。保护措施处的建议编号和标题可以点击查阅。建议页列出阶段、紧迫度、依据、实施前提和风险。续页末尾保留采纳／修改／否决、修改栏、理由栏和本页签名 |
| 签署页 | 复核人、角色、日期、签名，复核范围、录入方式、统计，以及人工新增内容的书写区 |

同时生成 `04_human_review.json`（用于录入复核决定，`pdf_page` 指条目首页）和 `04_review_form.md`（文字清单）。若有原图像素点、线、面标记，局部图按已有标记绘制。旧案例或范围待描记的条目继续以定位框呈现。

已有人工记录时，使用 `--force` 可重新排版同一草稿，同时保留已录入的决定、补充内容和签名。若原 AI 草稿文字或所录位置发生变动，为新草稿建立单独案例，保留原记录。

生成后逐页核对区域编号和图像位置、分页、目录页码和跳转。交付给实际复核人填写。

## 2. 复核人填写

由实际复核人（如修复师、文保研究人员、项目负责人）逐页选择 **采纳、修改或否决**。可以打印手写，也可以在 PDF 阅读器里批注，或在对话中明确告诉 AI 每条的决定。区域页的保护建议链接供查阅。请在对应的保护建议页填写对该建议的决定。

- 修改时写新的文字或字段；字典类条目和 `diagnosis` 可只写变动的字段。
- 否决时写理由。整体观察不能否决，只能用“修改”写明复核人确认的可评范围。
- 病害区域被否决后，引用它的保护建议也要复核：删除该建议，或改写依据和相关区域。不自动重编号。
- 可新增区域（未使用的编号、原图坐标、可见现象、暂定类型、证据）、建议或待核查事项。
- 涉及实体保护处理的建议，复核人宜注明是否经过现场评估。

## 3. 录入决定

把复核人的决定据实写进 `04_human_review.json`：每条的 `decision`、`revised`、`note`，以及 `reviewer`、`role`、`reviewed_at`、`signature`、`review_scope`、`entered_by`（例如“复核人本人填写”或“AI 按复核人 2026-11-26 对话意见转录”）。新增内容写入 `added_regions`、`added_suggestions`、`added_notes`。

复核人的身份、决定和签名只能来自复核人本人，AI 不得代填或推测。复核未完成时保留草稿状态，等待反馈。

## 4. 生成定稿

```bash
python <skill>/scripts/apply_review.py <案例文件夹>
```

脚本会拒绝缺项、草稿被改动、建议引用已否决区域等情况。通过后生成 `04_final.json`（定稿，每条带来源标记：AI 生成·人工采纳／AI 初稿·人工修改／人工新增）和 `04_change_log.md`（逐条的 AI 原文、决定、最终内容和备注），用于存档和追溯。
