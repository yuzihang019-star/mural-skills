# ① 病害识别（mural-screen v2）

```
【① 识别】→ ② AI 复核 → ③ 建议 → ④ 人工复核 → ⑤ 观察卡
```

这一步让视觉大模型**按一本固定的识别手册看图**，而不是随口描述。手册针对大模型看壁画最常见的三个毛病：只看整体漏掉小病害；把原画线条、浅色当成病害；没把握也说得很肯定。

## 文件

| 文件 | 作用 |
|---|---|
| `references/01_病害百科.md` | 每种病害：是什么、照片里长什么样、最容易和什么搞混、照片能不能确认（A/B/C 级）；误报清单 |
| `references/02_看图步骤.md` | 固定 6 步看图流程和检查表，**每次识别前先读** |
| `references/03_输出格式.md` | `01_findings.json` 的统一格式（Claude 版和百炼版共用） |
| `atlas/` | 对照图册：真实脱落 / 小模型误报 / 小模型漏检，来自 MuralDH 标注数据 |
| `scripts/` | 出图、放大、检查脚本；离线小模型 |
| `bailian/` | 百炼千问版本 + 有无手册对比测试，见 `bailian/README.md` |

## 流程（Claude 版）

1. 准备案例文件夹和看图用的图：
   ```bash
   python <skill>/scripts/screen.py <图像> <案例文件夹> --source "图片来源及授权" --team "队名"
   ```
   生成 `01a_whole.png`（整图+坐标刻度+分块）、`01b_tiles.png`（分块放大）、`01c_enhanced.png`（对比度增强）、`01_hints.*`（小模型提示）、空的 `01_findings.json` 模板。图片来源没给就问用户，可以先留空。
2. 读 `references/02_看图步骤.md`，按步骤看图。需要放大时：
   ```bash
   python <skill>/scripts/look.py <案例> zoom x,y,w,h x,y,w,h      # 多个框拼成一张，坐标用原图像素
   ```
3. 按 `references/03_输出格式.md` 填 `01_findings.json`，然后：
   ```bash
   python <skill>/scripts/check_findings.py <案例>
   ```
   通过后生成 `01_findings.png`、`01_crops.png`、`01_candidates.json`（② 读这个），并记录到 `workflow_log.jsonl`。不通过就按提示改。

**读图上限：整个流程不超过 5 次，不要直接读原图大文件**（会撑爆上下文）。对照图册按需读一张。

## 跟用户说什么

用大白话，一两句：看了几块、找到几处疑似病害、各是什么、哪些拿不准需要现场看；排除了哪些“像病害但不是”的地方。所有结论都是“疑似”，要经过 ② 复核和 ④ 队员人工确认。没找到病害就如实说，不要凑数。

## 能力边界（如实转述，不要夸大）

- 照片只能“初判”。起甲、空鼓、酥碱等主要靠现场敲击、侧光判断，照片上最多写“疑似”。
- 术语参照 GB/T 30237-2025《古代壁画病害与图示》，全文未公开，名称以标准原文为准。
- 离线小模型（NumPy 像素分类器，MuralDH 训练集 760 张训练）只认“脱落/露底”。测试集上它给的前 3 个框，10 个里约 2.4 个落在真实病害上（随机乱框约 1.4 个），见 `model/test_metrics.json`。它只用来提醒“这里再看一眼”，不能当结论。
- 手册对千问有没有帮助，要用 `bailian/eval_bailian.py` 实测，目前**还没有用真实百炼接口测过**。
- MuralDH 的标注只有“有/无病害”，没有类型，所以用它打分只能衡量脱落类病害。

## 其他脚本

`look.py`（重新出各种视图/放大）、`detect.py`（单图小模型）、`train.py` / `evaluate.py`（小模型重训和测试）、`build_atlas.py`（重做对照图册）。
