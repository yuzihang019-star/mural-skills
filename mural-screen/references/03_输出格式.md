# 统一输出格式（01_findings.json）

每次识别都必须按这个格式写。Claude 版和百炼版用同一个格式，方便对比和交给后面的步骤。

```json
{
  "image": "000504.png",
  "size_wh": [512, 512],
  "reviewer_model": "Claude Opus 5.5",
  "manual_version": "mural-screen v2",
  "overall": {
    "content": "坐佛及两侧胁侍，背景为火焰纹背光",
    "condition": "一般",
    "condition_reason": "佛像左侧大片颜料层缺失，其他部位基本完整",
    "photo_issues": "右下角有反光，该处不下结论"
  },
  "tiles_checked": ["T1", "T2", "T3", "T4"],
  "findings": [
    {
      "id": "F1",
      "bbox_xywh": [162, 27, 98, 332],
      "type": "疑似颜料层脱落",
      "category": "脱落类",
      "photo_grade": "A",
      "evidence": "佛像左肩至腰部成片浅黄色区域，边缘呈锯齿状，衣纹墨线在边缘处中断",
      "layer_exposed": "底色层",
      "confidence": "高",
      "alternatives": "排除原画留白：缺失边缘不随衣纹轮廓走，且切断了墨线",
      "how_to_verify": "侧光拍照看边缘是否有台阶",
      "source": "大模型看图"
    }
  ],
  "rejected": [
    {
      "bbox_xywh": [300, 120, 40, 90],
      "looked_like": "裂隙",
      "why_not": "是背光火焰纹的墨线，粗细有变化、随纹样弯曲"
    }
  ],
  "self_check": "4 条发现都写了排除理由；F3 为 C 级，信心已降为低"
}
```

## 字段说明

| 字段 | 必填 | 怎么写 |
|---|---|---|
| `overall.content` | 是 | 画了什么，一句话 |
| `overall.condition` | 是 | 只能是 `好` / `一般` / `差` |
| `overall.photo_issues` | 否 | 反光、模糊、压缩等；没有就写"无" |
| `tiles_checked` | 是 | 看过的分块编号，必须覆盖全部分块 |
| `findings[].bbox_xywh` | 是 | 原图像素坐标：左上角 x、y，宽、高 |
| `findings[].type` | 是 | 百科里的名称，前面加"疑似"（脱落类清楚的可以不加，但建议加） |
| `findings[].category` | 是 | 脱落类 / 裂缝类 / 结构盐分类 / 污染类 / 颜色变化类 / 人为损害 / 其他 |
| `findings[].photo_grade` | 是 | 百科里的 A / B / C |
| `findings[].evidence` | 是 | 只写看得到的：颜色、形状、边缘、和周围的关系。至少 10 个字 |
| `findings[].layer_exposed` | 否 | 底色层 / 地仗层 / 支撑体 / 不确定 / 无 |
| `findings[].confidence` | 是 | 高 / 中 / 低。**B 级最高"中"，C 级只能"低"** |
| `findings[].alternatives` | 是 | 你排除了什么误判、为什么 |
| `findings[].how_to_verify` | B/C 级必填 | 侧光拍照、敲击、取样、查档案…… |
| `findings[].source` | 是 | 大模型看图 / 小模型提示后确认 |
| `rejected[]` | 否 | 看着像但判断不是的，写上理由，评审很看重这一项 |

## 和后续步骤的关系

`check_findings.py` 会把 `findings` 转成 `01_candidates.json`（候选编号 1、2、3……，`type_hint` 就是你写的 `type`），② `mural-review` 直接读它。原来的小模型结果另存为 `01_hints.json`，不再直接当候选。
