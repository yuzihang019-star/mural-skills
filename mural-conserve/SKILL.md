# ② 写保护措施和壁画报告

读取案例里的 `02_review.json`、`case_meta.json` 和基准照片。查 [保护措施方向](references/01_保护措施方向.md) 及 [案例写法与制图参考](references/02_案例写法与制图.md)。只把与本案有关的资料写入报告，并说明用它核对了什么。

## 写给要看图和做决定的人

- 区域页按 **可见现象、病害判断、人工核查方法、保护措施** 排列。判断以有证据支持的病害名称开头，例如“疑似起甲”“表层脱落，层位未明”。接一句依据，只有另一个解释会改变行动时才写进去。
- 人工核查写清到哪里、怎么看、看到什么会改变判断。例如：“请从左右两侧打斜光，查看褐斑边缘有没有台阶。”用“作为下次对照的照片”“补拍近照”“现场看看”这类顺口的说法。保留颜料层、地仗、起甲等有实际含义的术语。
- 每处给一个眼下能做的动作。有现场证据才定实体处理。疑似时按“先检查……。如果确认……，由文保人员评估……”写。稳定边缘可记录后定期对照；有松动或掉落迹象时先由管理方保护现场、由文保人员评估。
- 同类区域可共用一条措施。标题用具体动作，例如“查清眉部褐斑是凹缺还是覆盖”。报告会在对应区域的「保护措施」里显示措施标题和编号，切勿把区域编号留在散文里而漏填 `related_regions`。确需各区不同的做法就分条。
- 交代对象位置、图像来源、已知材料、旧修和保存环境，缺失项集中交代一次。明确优先检查什么和原因。照片依据的等级只表示判断有多少影像支持，核查优先级和措施紧迫度各有用途。

## 生成报告

```bash
python <本技能>/scripts/init_conservation.py <案例> --model "<实际使用的模型>"
python <本技能>/scripts/check_conservation.py <案例>
python <本技能>/scripts/make_report.py <案例>
```

报告脚本使用 Pillow 和 ReportLab。需要指定中文字体时，可用 `MURAL_CJK_FONT` 指向中文 TrueType 字体。

在初始化和校验之间填写 `03_conservation.json`：

| 字段 | 写什么 |
|---|---|
| `object_context`、`overall_strategy` | 对象和已知条件，重点部位、先后顺序及实物处理前提 |
| `suggestions` | 顺序排列的措施。可为空 |
| `uncertainty`、`human_check_points` | 会改变决定的证据缺口，交给具体人员的检查事项 |
| `references` | 实际用过的资料，每条有 `name`、`note`，有网页或 PDF 时加 `url` |

每条措施写 `no`（唯一正整数）、`title`、`content`、`related_regions`、`basis`、`preconditions`、`risk`。整体措施用空数组关联全幅。 `category` 可用保护、数字展示、公众传播。后两项按用户需要填写。保护类必填 `stage` 与 `preconditions`，阶段为调查诊断、预防性保护、应急稳定、修复处理或监测。 `urgency` 为紧急、优先、常规或随访，紧急用于已有坠落或快速恶化迹象的情况。

`03_report.pdf` 是供阅读和讨论的 AI 草稿。封面总览后按分区看图和读条目，再看措施详情。原图坐标用于找到位置，有尺度证据才能写实物尺寸。放大图按已有标注展示点、线或面，矩形表示需查看的范围。逐页检查文字、图号、图例及页码。另用 `mural-review-pdf` 生成独立的 `04_review_form.pdf`。
