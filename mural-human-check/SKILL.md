# ④ 人工复核（mural-human-check）

```
① 初筛 → ② AI 复核 → ③ 建议 →【④ 人工复核】→ ⑤ 观察卡
```

这是整条流程里唯一由人做决定的环节，也是评分表里“人工复核设计”“不确定性与人工复核提示”的直接证据。AI 只负责把内容整理成方便判断的复核单，并照实记录人的决定。

## 铁律：AI 不得代替队员做决定

- 不要自己填写 `decision`、`reviewer`、`signature`，也不要“先帮你填好，你看看行不行”。
- 每一条的决定都必须来自用户在对话里明确说出的意见，或者用户自己编辑过的 `04_human_review.json`。
- 如果用户说“都采纳吧”，要提醒一次：评委会看修改记录，逐条认真看过更可信；用户坚持的话，照实记录为“采纳”。
- `entered_by` 照实写：“队员本人编辑” 或 “AI 按队员口述逐条录入”。

赛题规则把伪造过程记录、隐瞒 AI 使用列为取消资格的情形，所以这一步不能走捷径。

## 步骤

1. 生成复核单：
   ```bash
   python <skill>/scripts/make_form.py <案例文件夹>
   ```
   产物：`04_human_review.json`（待填写）、`04_review_form.md`（可打印的勾选表）、`04_review_sheet.png`（每个区域的局部图 + AI 原文 + 勾选框，适合在视频里展示“人在看”）。

2. 把复核单交给用户。两种方式任选：
   - 用户自己编辑 `04_human_review.json` 或在 `04_review_form.md` 上勾选后告诉你。
   - 你逐项向用户提问（可以用选择题：采纳 / 修改 / 否决），用户回答后你按原话录入。选“修改”的，请用户说出改后的内容。

   同时问清：复核人姓名、角色（如“队员，美术学专业”）、日期、签字（可以是姓名确认）。也问一句有没有要“人工新增”的区域、建议或复核点。

3. 录入格式：
   - `decision`：采纳 / 修改 / 否决
   - `revised`：选“修改”时填；格式与 `ai` 相同，可以只写改动的字段
   - `note`：复核人的理由（有就写，评委爱看）
   - `added_regions[]`：人工新增区域，字段同 ② 的 regions（含 `label`、`bbox_xywh`、`phenomenon`、`type`、`evidence`、`impact`、`confidence`）
   - `added_suggestions[]`、`added_notes[]`：人工新增的建议、复核点

4. 应用复核：
   ```bash
   python <skill>/scripts/apply_review.py <案例文件夹>
   ```
   任何一项没决定、签字没填，都会拒绝生成。通过后输出 `04_final.json`（每条带来源标签：“AI 生成 · 人工采纳”/“AI 初稿 · 人工修改”/“人工新增”）和 `04_change_log.md`（AI 原文与最终内容逐条对照）。

   复核后区域不在 1–3 处、建议不在 1–2 条时也会报错，请用户补充或调整。

5. 告诉用户采纳、修改、否决各几条，提示进入 ⑤ `mural-card`。

## 录视频提示

这一步建议真人出镜或录屏操作：打开 `04_review_sheet.png`，对照原图讲一两处“为什么改”或“为什么否决”，再展示 `04_change_log.md`。“AI 说的不全对，人做了纠正”是最有说服力的人机协同证据。
